## Design Document — Iteration 2
### What the measurements say (and what they don't)
MGS = **0.2857**, target 0.85. The marginal decomposition is unambiguous: **U is the binding term** (marginal 0.714), A = 0.0, F = 0.0. A and F are already perfect, so this iteration spends *all* of its effort on U and must spend none of it on mechanisms that touch A or F.
The previous critique is thorough and its counter-evidence is convincing: for all five failing checkpoints the candidate scan returned allowed rows (`allowed >= 2`, often `allowed=8`), every answer was non-empty, and no retrieving checkpoint hit a tombstone. **Retrieval, gating and indexing are demonstrably working.** Three failure mechanisms sit above the storage layer, in two files we own:
1. **wrong_action_shape** (`_ckpt_09`, and the action-label half of `_ckpt_06/08/02`): `retrieve()` Gate 2/3 counts *every* chart row the requester is not cleared for into `denied_rbac`/`denied_scope`, including rows completely unrelated to the query. `sanitize_and_decide` rule 3 then downgrades a correct `answer` to `answer_redacted` because a narrow query happens to share a chart full of unauthorized-but-off-topic noise (e.g. 23 denied rows for an HIV query that never asked about 23 things). This is a **counting bug in the denial accounting**, fixable in `retrieve()` with no DDL.
2. **evidence_withheld** (`_ckpt_01`): the LLM answerer, handed 4 fully-cleared evidence records, emitted `no_memory`/`refuse` via the unclamped override `action = str(rendered.get("action") or action)`. That is a one-line clamping bug in `agent.py::query`.
3. **answered_but_content_missing** (`_ckpt_06/08/02` content half): the model was handed 8/8/4 gated evidence records and cited only 2–4, dropping required content. The harness cannot be changed (it is outside this artifact), so the agent must **guarantee coverage in-artifact** rather than trust a weak answerer.
### The plan (three code changes, one incidental index)
**Change 1 — responsive-only denial accounting (`store.py::retrieve`, design, P1).** In Gate 2 (role grant) and Gate 3 (relationship/scope), a record counts toward `denied_rbac`/`denied_scope` **only if it is responsive** (shares at least one distinctive term with the query, or the query is empty). Off-topic denials are still denied (they never enter `decision.allowed` — the policy is untouched), still logged for the audit trail (same `deny_rbac`/`deny_scope` codes, keeping `test_every_denial_is_audited` green), but are **not appended to the counter lists**, so `touched_unauthorized` reflects only responsive denials and rule 3 no longer mislabels a clean `answer` as `answer_redacted` because of chart noise. Compute the record's terms by decrypting the body in-process when needed (never returned). **Tombstone branch is untouched** — `touched_deleted` stays unconditional so `no_memory` still wins over everything, preserving F. Effect: `_ckpt_09` becomes a clean `answer`, and the action labels for `_ckpt_06/08/02` collapse to `answer`.
**Change 2 — clamp the LLM action override (`agent.py::query`, design, P2).** When `sanitize_and_decide` returns `answer` or `answer_redacted`, the model may reword the content but must never emit `no_memory` or `refuse`; the worst permitted override is a one-step downgrade to `answer_redacted` (in case the model spotted something sensitive in the cleared evidence). This blocks the `_ckpt_01` refusal and prevents the model from re-issuing redactions after Change 1 fixes the labels.
**Change 3 — exhaustive evidence coverage (`agent.py::query`, design, P3-in-artifact).** The previous critique correctly labels content-dropping as an answerer fault, but the agent does not have to accept it. After the LLM returns for `answer`/`answer_redacted`, run a deterministic coverage pass: for every `e in decision.allowed`, if the model's answer contains **no** distinctive term from `e.body`, append `" Additionally: {e.body}"`. The appended text is the exact cleared evidence, so it cannot widen policy (nothing here wasn't already released); it guarantees the answer represents every cleared record regardless of model willingness. This directly attacks the content-missing half of `_ckpt_06/08/02`.
**Incidental schema change (does not target U).** The retrieval hot path needs no DDL — the prior indexes are doing their job and the critique's counters prove it. The one genuinely useful improvement is an index on `access_log(checkpoint_id)` for the Critic's per-checkpoint audit queries (the local test gate and the Critic both read the audit log by checkpoint). It costs nothing on U/A/F and is the only migration emitted. `SCHEMA_VERSION` bumps 2 → 3 in both `store.py` and `schema.sql`.
### Why A and F stay at 0.0
- **A:** Change 1 never releases a record the policy denied. On-topic denials still force `refuse`/`answer_redacted`; only off-topic denials stop downgrading the label, and those records were never shown anyway. Change 2 clamps toward *more* permissive, not less: it can turn a wrong `no_memory` into an `answer` that was already cleared. Change 3 appends only already-cleared bodies.
- **F:** `touched_deleted` handling in Change 1 is explicitly left unconditional, and Changes 2–3 only run on non-tombstoned releases. The three active-forgetting tests (`test_tombstone_beats_authorization`, `test_deleted_content_is_not_retrievable_by_anyone`, `test_crypto_shredding_destroys_the_key`) are untouched.
Net: the multiplicative product moves because U rises while (1−A)(1−F) stays 1.0.
