## Design document — iteration 1 (standard_retrieval curriculum)
### What the measurements say before this iteration exists
This is a green-field iteration: `U=0.0000 A=1.0000 F=1.0000`, `MGS=0.0000`, and the developer local gate is failing with 0.000 pass rate. There is no prior run whose delta can be mined, so the curriculum phase (`standard_retrieval`) and the shape of the local tests are the only evidence. Three facts are load-bearing:
1. Every local test file is a contract that is already passing for the supplied baseline and must keep passing. That pins the RBAC policy, the tombstone ordering inside `sanitize_and_decide`, the responsiveness-before-policy gate ordering, the `top_k` hard cap, the keyed-hash term index, and the key-shredding semantics.
2. The biggest source of measured MGS loss in this codebase's own docstring history is **loss of the action label on authorized queries**: allowed-and-nothing-denied must come out `answer`, and a denial list must only ever mean *responsive* content was withheld. That invariant is already implemented and must not be disturbed.
3. The only open utility surface left in that architecture, once the label bug is fixed, is **what enters the `allowed` bucket for a fully authorized requester** — i.e. gate-0 recall/ranking — because the benchmark scores `action == expected and include_ok`. If the right record never reaches `allowed`, the answer misses required strings; if the *wrong* records are picked first by the `top_k` cap, the same thing happens.
### What this iteration changes, and which metric it targets
**`targets_metric`: U (utility accuracy on authorized queries).**
`A` and `F` are protected — the policy tables, the grant join, the gate order, the tombstone-beats-everything branch, and the key-shred path are all left bit-identical for their existing inputs. The change is confined to:
1. **How distinctive terms are derived for the gate-0 index.** `_distinctive_terms` keeps its current exact-token behavior for source text, but a new deterministic morphological variant set (stripping plural/simple-tense suffixes) is appended on **both** the ingest side (`_index_record`) and the query side (`retrieve`). Because both sides hash the same variant list, an authorized user can find `result` with a note containing `results`, or `counseled` with a note containing `counsel` — real clinical phrasing gaps that currently make a record look non-responsive and silently drop it from `allowed`. The index remains purely hash-based; no plaintext vocabulary is introduced, `test_a_confidential_body_is_not_stored_in_the_clear_by_the_index` still passes (the words `methadone` / `hepatitis` still never appear in any row).
2. **Candidate ordering before the `top_k` cap.** `retrieve()` already enforced the hard cap; the defect is that it scans `ORDER BY seq DESC`, so the *most relevant* evidence can fall outside the cap while marginal-but-recent evidence fills it. This iteration ranks gate-0-qualified candidates by term-overlap with the query (then sequence as tiebreak) *before* feeding the `top_k` cut. The cap stays a hard cap — exactly 8 cleared for the tested case — which is the regression the docstrings warn about; only *which* 8 are selected changes, in the direction that matches the query.
3. **Forgetting hardening:** `shred()` additionally zeroes the stored ciphertext bytes. `test_crypto_shredding_destroys_the_key` only asserts the key row is nulled and `_decrypt` returns `None`; clearing the byte string is a strict strengthening (current row payload is recoverable *if* the key ever returns via a bad restore; after this it is not).
Nothing in the three changes introduces a new read path from a denied record: the overlap rank operates only on rows that already passed gate-0 (or walked the tombstone fallback), and gate 1–3 logic is untouched. The expected cost to `A`/`F` is near-zero: the variant dictionary is deliberately conservative (no aggressive stemmer; only ≤2-char suffix removal on ≥5-char tokens), so it cannot pull *irrelevant* records into the gates with any material frequency, and the forgetting change only makes the active-forgetting path *more* destructive.
### Schema delta
One new index accelerates the term-overlap pass added to the gate-0 retrieval loop:
- `idx_record_terms_lookup ON record_terms(record_id, term_hash)` — the overlap ranking joins `record_terms` by `record_id` and probes by `term_hash`; the composite index serves both directions in a single read, whereas today only the `(term_hash)` index exists.
No table or row shape changes: `records`, `tombstones`, `crypto_keys`, `role_grants`, `relationships`, `access_log` and `store_meta` all remain exactly as the local tests construct them.
### Retrieval loop (revised)
```
query_text -> _distinctive_terms -> exact hashes
              + _morph_terms      -> variant hashes        (gate 0, keyed HMAC like today)
```
1. Scan shard rows (`patient_id`), unchanged gate logic per row:
   - gate 0: live record responsive iff any query-hash (exact or variant) hits `record_terms`; tombstoned ⇒ responsive (conservative); empty query ⇒ responsive for all.
   - gate 1: tombstone ⇒ `denied_tombstone` (logged).
   - gate 2: missing `role_grants` row ⇒ `denied_rbac` (logged).
   - gate 3: relationship+scope fail ⇒ `denied_scope` (logged).
   - allow ⇒ decrypted plaintext into `allowed`.
2. Collect the responsive live rows and their overlap counts; keep tombstone rows on the fallback list.
3. Merge, sorting by (overlap DESC, seq DESC); fill `allowed` only up to `top_k`. The cap is unchanged, so an evidence-collection regression cannot recur.
### Forgetting mechanism (unchanged policy, hardened erasure)
`tombstone()` → in one transaction: tombstone row; purge the record’s variant index rows; for encrypted records `shred()` the key **and** the ciphertext; for plaintext records overwrite `body=''`. Existence remains knowable internally (`is_deleted`) but never answered; a subsequent identical ingest does *not* un-delete (verified in the forgetting tests).
### Work order (Delta)
The work order is a delta on the baseline — every step names a change to an existing source file and must not regress any of the lifecycle, RBAC, forgetting, or utility tests the Developer inherits.
1. **`A`:** Add a small deterministic, reversible token-morphism: `_morph_terms(text) -> set[str]` yields for each legacy distinctive token the token plus (if length ≥ 5) one suffix-reduced form (remove trailing `s`/`es`, or trailing `ing`/`ed` when the residual is ≥ 4 chars). Keep it pure and cacheable; do not attempt a general stemmer.
2. **`B`:** Change `_index_record` so the digest set it writes to `record_terms` is built from `distinctive_terms(text) ∪ morph_terms(text)` (both keyed-hashed by the *same* `_index_key`) — so ingest stays in lockstep with query-side variants and a restored/resumed store keeps matching after reopen.
3. **`C`:** Change `retrieve()` to derive the candidate-match hashes the same way: `query_hashes = hashes_of(distinctive_terms ∪ morph_terms)`, and (upstream of the loop) build a per-record overlap count instead of the current boolean hit/miss. Keep the empty-query and tombstoned fallbacks exactly as today.
4. **`D`:** Reorder candidate iteration by overlap (desc) then `seq` (desc) *before* honoring the `top_k` cap on `allowed`; leave log writes, gate side-effects and denial-list construction in the same order for the same rows.
5. **`E`:** Strengthen `shred()` to also write `ciphertext = NULL` (or zero-length `BLOB`) into the record row in the same transaction, so the ciphertext no longer outlives the key. Prefer byte-order zeroing: `UPDATE records SET key_id=NULL, ciphertext=x'' WHERE record_id=?`.
6. **`F`:** Add the supporting unit test(s) for the two new behaviors without weakening any contract test: (i) authorized requester retrieves a record across a singular/plural or tense boundary; (ii) the `top_k` filler prefers the higher-overlap qualifying record when choosing among cleared evidence.
7. **`G`:** Append explicit migration/DDL statements in the design JSON: `ALTER TABLE` none; `CREATE INDEX idx_record_terms_lookup` with one-line rationale.
Everything else (RBAC join, scope checks, `sanitize_and_decide` labels, tombstone-beats-everything, field wall, per-episode file layout) is untouched.
