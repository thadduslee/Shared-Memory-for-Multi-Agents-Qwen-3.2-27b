# Iteration 11 — Design Document
## 0. Reading the table first
The last iteration **tied** the champion, and this is now the 5th consecutive non-improving iteration (6 regressed, 7/8 tied, 9 regressed, 10 tied). Critically, **iteration 10 is already the revert** of iteration 9's top_k 64→16 error — its raw terms match iteration 5's champion exactly (U=0.6111, A=0.0588, F=0). There is nothing left to revert; the stall is not caused by a bad active change. I agree with the previous critique's verdict: `not_the_cause`. The 7 remaining U failures are untouched by any of the last five iterations' edits, because they sit in *denial-admission and ranking logic*, not in the top_k value (they existed at iteration 5 under the same cap).
So the mechanism the last several iterations kept pushing — top_k / evidence-set breadth / answer-prompt assembly — has been measured wrong repeatedly and I will **not** touch any of it this iteration.
## 1. What the census actually established
The previous critique's census is unusually concrete because the failing checkpoints' *call sites* are unambiguous:
- `allowed=16, denied_rbac=0` (ckpt_09, ckpt_10, ckpt_03): the gold record **ranked out** under the cap. Ranking is the suspect — but the specific fix (stop demoting structural overlap on pure-logistics queries) is **not yet confirmed**, because no iteration has ever seen the ranked candidate list for these checkpoints.
- `denied_rbac=2..3, got the wrong label` (ckpt_04/05/16): the marginal `query_answer_denials` digest-equality mislabels an otherwise-complete answer as `answer_redacted`. The exact digest geometry of those denials is **also unobserved**.
- `allowed=16, denied_tombstone=4, action=no_memory` (ckpt_17): a deferred tombstone was admitted even though live cleared records re-state the asked-about fact in different words. The mechanism here is **crisp**: the deferred-tombstone coverage skip demands exact-digest subset (preserved tombstone digests ⊆ covered_union); a live paraphrase has *different* digests, the subset test fails, the tombstone is admitted, and `sanitize_and_decide`'s "tombstone beats everything" branch forces `no_memory` on a question that live, cleared evidence already answers.
The previous critique's #1 complaint about iteration 10 is correct and is the key structural insight for iterating under a scored loop: **an evidence-gathering iteration that emits no evidence is a wasted round.** Iteration 10 planted a `candidate_census` on the Decision and never serialized it anywhere any later iteration could read. Iteration 11 *must not* repeat that.
## 2. Plan: one behavior fix (P4) + make the census observable (P1). Nothing else.
The instruction says to **change the mechanism or narrow the change until you can see which part helps**. P2 (structural-demotion ranking) and P3 (digest-equality marginal accounting) are exactly the "fourth blind guess" the census warns against — both depend on seeing the ranked/denied candidate geometry that **no iteration has ever observed**. Acting on them now, without the census, is how this run stalled five times. I deliberately defer them one round.
What I *will* do:
**P4 — query-center the deferred-tombstone coverage test (fixes ckpt_17).**  The mechanism is fully specified by the census and is guarded by existing tests on both sides. The coverage skip currently asks "is the tombstoned record's preserved digest set an exact subset of what live allowed records cover?" A paraphrase of the deleted fact (different day-form, different phrasing of the Harbor Guest back line) produces different digests → subset fails → tombstone admitted → `no_memory`, even though the question is answerable from records that cleared every gate. Change the test to be **query-centered**: a deferred tombstone is admitted (forcing `no_memory`) only when the tombstone's *query-matching real-content* digests are **not** already present in the covered union — i.e. when the live cleared evidence does **not** already carry what the query asks about. If the live allowed set holds every real-content digest of the question that the tombstone would deny, answering from live bodies cannot reconstruct anything that was not already in cleared evidence, so the tombstone must not fire.
Three guardrails keep A and F at their current values:
- The relaxation only **removes a record from `denied_tombstone`**; it never adds anything to `allowed`. The allowed set — the only content ever emitted — is byte-identical to today. A is untouched.
- If the query shares **no** real-content digest with the tombstone's preserved set (the tombstone would have been admitted on structural/contact overlap alone), keep the current conservative behavior and admit. This preserves the F contract that a badly-understood deletion still reads as `no_memory` (it keeps `test_a_tombstoned_record_is_assumed_responsive`, `test_tombstone_beats_authorization`, `test_deleted_content_is_not_retrievable_by_anyone`, and `test_deletion_survives_reingestion_of_similar_text` green, because in every one of those the queried content is *not* carried by a live allowed record).
- `sanitize_and_decide` branch 1 is **untouched** — the hand-built `Decision(allowed=…, denied_tombstone=[…])` unit test still asserts `no_memory`. The relaxation happens strictly at admission time in `retrieve()`, where the live `covered_union` is actually known.
This is a narrow, code-level change in one function, with one clear expected win (ckpt_17 → U 11/18 → 12/18, ≈ MGS 0.5752 → 0.6275, breaking the stall) and a bounded downside.
**P1 — make the candidate census actually readable.**  In `retrieve()`, after PASS-1 produces the full ranked candidate list, capture the top `top_k + 24` gate-0 survivors into `decision.candidate_census` as `(record_id, overlap_total, overlap_content, seq, rank)` **verbatim from the sort, before any gate is applied**. The 24 beyond the cap are *observed, never acted on* — they are added to neither `allowed` nor any denied list, so this is provably branch-free for the decision and cannot raise A (the exact regression mode that halved U in earlier runs — records reaching the gates that did not before — is structurally impossible here because the census does not feed any gate). Then in `agent.py`, `query()`'s `debug` dict serializes the census (trimmed) as `debug["candidate_census"]`. The `_eval_runner` already carries `debug` into `SHARD_RESULT`, so the next iteration will finally be able to see, per failing checkpoint, *which record ranked where and whether the gold was ranked out vs. denied* — the exact data P2/P3 need before they can be safely attempted.
No DDL is proposed. None of the seven failures is a lookup/deletion-visibility problem, and the observability and tombstone fixes are runtime logic. Adding an index or column would be churn with zero measured benefit.
**Why this is not a fourth iteration of a measured-wrong strategy:** the last five iterations all varied *evidence-set breadth / top_k / answer-prompt assembly*. This iteration changes the *conditional admission of a tombstone* (a decision-logic mechanism not touched since iteration 4) and adds the census serialization that iteration 10 planted but never made observable. If P4 works, we get a new best with real signal; if it does not, P1 ensures the *next* iteration is not blind, which is the thing every stall since iteration 7 has lacked.
**Target:** U (+1 checkpoint = +0.0556 U ≈ +0.052 MGS at fixed A/F). **Costs:** F carries a small, heavily-guarded risk from the tombstone-admission relaxation (mitigated by the real-content-overlap requirement and the allowed-only coverage check); A is structurally untouched because the allowed set and all grants are unchanged; the census costs a little CPU and nothing else.
