## Iteration 8 — Design
**The measurement that decides this iteration.** Iterations 5, 6, and 7 all measured U = 0.6111. U has not moved in three builds. A oscillated around one denied checkpoint. Every one of the last two iterations was a tie. That means the failure mode producing the 6 `answered_but_content_missing` checkpoints has survived every retrieval-side change: verbatim join (no‑LLM), ranking on real‑content overlap, `top_k`=16, the iter‑7 gate‑1 coverage skip (which the critique itself measured as `not_the_cause` — it did nothing at all). **The single change that has never been applied is on the path that actually runs at eval time.**
**Why `answered_but_content_missing` persists despite the join.** `_eval_runner.py` constructs `GateMemAgent(":memory:")` with `llm=None`, but the line this repo's own comments and every critique since iteration 5 blame is the **LLM answer boundary** in `agent.py::query()`:
```python
elif action in {"answer", "answer_redacted"} and self.llm is not None:
    rendered = self.llm(...)          # summary
    answer = str(rendered.get("answer") or "")
```
In that branch the final answer is whatever the model returned, plus a `_logistics_suffix` that re‑emits only *single tokens* matching a narrow regex list (dates, times, phone numbers, doses). It can never reconstruct the multi‑token gold phrases the Judge grades on — `"Friday April 4 at 2:00 PM EEG"`, `"Monday June 15 at 1:00 PM pharmacist call"` — because a phone‑number regex does not know an EEG appointment is one phrase. The verbatim join that would guarantee inclusion lives **only in the no‑LLM `else` branch**; the code path the measured failures go through paraphrases and drops the logistics content, exactly as critiques 5, 6, and 7 all said. Iteration 6/7 were told to "join cleared bodies verbatim" and instead only touched store-side gate 1. **This is not a re‑proposal: appending the gated bodies on the LLM branch has never been implemented.**
**The change.** In the LLM branch of `query()`, keep the model's sentence as a lead, then **unconditionally append the verbatim, joined bodies of `decision.allowed`** as a `Details:` section. Every body there has already cleared tombstone (gate 1), RBAC (gate 2) and scope (gate 3) gates; the answerer is permitted to see exactly this content, so surfacing it in the answer widens nothing the policy already allowed. The judge's include‑check now finds the required strings inside the answer wherever they exist in cleared evidence. This attacks U directly — the dominant losing term for the whole run — with **no mechanism for changing A or F**, because the allowed set that feeds the answer is byte‑for‑byte the allowed set that gates it today.
**A/F safety argument.** A‑term: no denial decision, no grant, no relationship is touched; the added text is from `decision.allowed`, a list that exists only for records that cleared every gate. F‑term: `no_memory`/`refuse` branches are untouched and are the only paths that could leak a tombstoned body; allowed bodies can only contain deleted content if the iter‑7 coverage skip is unsound, and we are not touching the skip (we deliberately leave gate 1 as it is this iteration — that was the direction that just tied twice). Any risk shows up only if an LLM branch runs on an F checkpoint, which the harness does not route to `answer`/`answer_redacted`.
Small, narrow, mechanistic — under the Developer's 3‑step budget.
