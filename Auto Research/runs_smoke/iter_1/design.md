## Iteration 1 design — GateMem memory system
**Read of the measurements.** U = 0.0, A = 1.0, F = 1.0 is the all-failure state a fresh baseline starts from. Because MGS is `U * (1-A) * (1-F)`, fixing A or F alone multiplies U by a factor that is still 0 — only once both A and F are ~0 does improving U translate into MGS. The template already ships a solid RBAC join (`role_grants` × `relationships`, three ordered gates) and a tombstone+shred layer that its own unit tests pin down. The measured F = 1.0 therefore points at the mechanism the local suite *cannot* catch: deletion that is anchored to a *specific record* and matched by a fragile keyword-overlap. The benchmark's forgetting probes paraphrase, re-present, and query around a deleted fact; a record-scoped tombstone misses all three. Costs the system the F term outright.
**What this iteration targets.** `F`, the active-forgetting failure rate. The design keeps a *concept-anchored* denylist of forgotten facts alongside the existing record tombstones, so that (a) a later note re-presenting the same fact is tombstoned at ingest, (b) any retrieval path — index scan, migration, agent fallback — that would surface the fact is suppressed as `deny_tombstone` and therefore reads `no_memory`, and (c) the crypto-shred and in-place body wipe stay as the irreversible layer. Cost to the other terms: `U` loses a hair (a legitimately re-introduced fact that the patient explicitly asked to forget stays suppressed — which is the correct medical behaviour), `A` is unchanged to slightly improved (the denylist suppresses to *everyone*, authorized or not, adding no new grants).
**Retrieval loop (revised).** Gate order becomes: (0) record tombstone, (0b) *denylist overlap* — both classified as `denied_tombstone` so an authorized clinician gets `no_memory`, never an answer; (1) role grant (`role_grants` LEFT JOIN); (2) relationship + scope. A new pre-RBAC step decrypts any plaintext needed for the denylist check; the decision never leaves the store until all gates pass. This keeps `sanitize_and_decide`'s ordering intact (tombstone-beats-authorization).
**Forgetting mechanism (revised).** Persist the *terms* of every honored deletion request into a new `forgotten_facts` table per episode; at ingest and retrieve, any record whose plaintext overlaps the denylist by ≥2 distinctive terms is treated as deleted. Cryptographic shredding of `crypto_keys.key_material` and the in-place `body=''` wipe remain the irreversible backstop.
**Schema/migration.** Baseline DDL is the template's `schema.sql` (kept verbatim). The migration adds `forgotten_facts`, plus two indexes that speed the two dominant query paths (the delete-scan and the retrieval scan). `SCHEMA_VERSION` bumps to 2.
