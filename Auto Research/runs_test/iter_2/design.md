The measured data points squarely at the retrieval pipeline. The census is unambiguous: all six failing checkpoints are design faults in `MemoryStore.retrieve()` and the downstream `sanitize_and_decide()` action mapping, with **U** contributing 0.7347 of the MGS deficit. `F` is already 0.0000 and the local test gate is green — the risk this iteration is not being too aggressive on policy, it is touching the allow-set in a way that leaks.
My design keeps the two hard invariants intact and uses the room the data leaves. All three mechanisms share a single root cause: **relevance is checked after the RBAC gates, so an irrelevant record that fails RBAC is tallied as a denial, flips `touched_unauthorized`, and the agent answers `answer_redacted` (or `no_memory`) instead of `answer` — even when the answer contains every required string.**
The fix is a faithful reordering plus a recency fallback, and the key correctness argument is that **nothing in the reorder widens `decision.allowed` beyond what RBAC already grants**. Every record that reaches the allowed set still passes Gate 1 (tombstone), Gate 2 (role grant), and Gate 3 (relationship+scope). What changes is only *which* records get counted as denials — and it is the counting that drives the action label, which is what the Judge reads.
**Mechanism 1 (`answered_but_content_missing`)** — the relevance veto runs *after* gates 2/3, so the helpline/afib/early-pregnancy records get counted as `denied_rbac`, flip the action to `answer_redacted`, and the content is withheld even though the requester was authorized. Fix: move the term-overlap veto **above** gates 2 and 3 so an irrelevant record is skipped silently (no `denied_rbac`, no `access_log` entry, no `touched_unauthorized`). Recency fallback: the first record that reaches the RBAC section is always evaluated even if it doesn't overlap the query — this keeps the most recent clinically actionable record from being excised by a topic mismatch. And `top_k` rises 8→16 so the hard cut no longer truncates long episodes.
**Mechanism 2 (`wrong_action_shape`)** — same root cause: tens of unrelated denials inflate `touched_unauthorized`. With the reorder, `denied_rbac`/`denied_scope` only ever contain records that were *either* topic-relevant *or* the recency-fallback record — i.e. legitimate denials. `sanitize_and_decide` is **unchanged**; it already maps `allowed + touched_unauthorized → answer_redacted` and `allowed + clean → answer`. The data feeding it is now honest, so the label tracks query relevance. I deliberately did *not* add the `denied_relevant` flag from the prior critique: with the veto above the gates, its presence is redundant, and a freshly constructed `Decision(denied_rbac=[...])` (as the local test does) must still map to `answer_redacted` — the unfiltered-flag version would silently regress that testgate. Minimal change wins.
**Mechanism 3 (`evidence_withheld`)** — an empty plaintext with a NULL tombstone was being inferred as a deletion, poisoning the `no_memory` branch. Fix: guard the empty-plaintext branch on `row["tomb"] IS NOT NULL`; otherwise silently `continue`. A record that is tombstoned *and* has no readable plaintext still hits Gate 1 first (tombstone beats everything) and reads `no_memory` as required — so the F metric's `test_deleted_content_is_not_retrievable_by_anyone` and `test_tombstone_beats_authorization` stay green. I am not adding the `if decision.allowed: return "answer"` last-resort the prior critique suggested: placed after the redaction branch it would let an `allowed + denied` decision report a clean `answer`, which is exactly what Mechanism 2 is trying to prevent. Dead guarded code is a regression risk, not a fix.
**Tradeoff.** The target is U. The recency fallback inserts *one* authorized-but-maybe-off-topic record into the answer when nothing relevant survived; since it only ever passes records that already cleared all three gates, the authorization surface (A) is unchanged, and F is untouched because Gate 1 runs before any of this. The schema change is a single index on `records(patient_id, seq DESC)` to make the per-patient recency lookup cheap; no columns or `ALTER` statements are needed — the `Decision` dataclass gains no fields.
