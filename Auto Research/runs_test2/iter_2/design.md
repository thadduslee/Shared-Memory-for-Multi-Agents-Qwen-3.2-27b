The three failures identified by the Critic all live in the retrieval/decision layer, not in the schema or storage. The fixes are targeted, surgical, and do not touch a single line of SQL. I am therefore leaving the schema untouched — no DDL changes are required — and spending this iteration entirely on the two Python modules that drive `U`.
**Fix 1 — Denial relevance filter (store.py)**  
Currently `retrieve()` appends a row to `denied_rbac` / `denied_scope` whenever the RBAC or scope gate fails, *without* checking whether that row is actually responsive to the query. A sibling record that shares a few FTS terms but contains no answer-relevant content inflates `touched_unauthorized`, which demotes a clean `answer` to `answer_redacted`. The fix is to compute the plaintext (from `body` or via decryption) and apply the same `terms ∩ distinctive_terms(plaintext)` relevance check that the allowed path already uses. If the row is irrelevant, we `continue` and never record a denial or an audit log entry. This makes `touched_unauthorized` reflect only denials that matter to the question.
**Fix 2 — No LLM action override (agent.py)**  
`sanitize_and_decide` is the deterministic policy authority. The previous code let the LLM override the action, so a refusal could be injected even when the store had cleared content. The fix is to keep the action returned by `sanitize_and_decide` unconditionally and use the LLM only for *phrasing* the answer text, never for deciding whether an answer is given. Since we are also switching to concatenation (Fix 3), the LLM becomes optional; the action is always taken from the policy.
**Fix 3 — Verbatim answer assembly (agent.py)**  
The measured `answered_but_content_missing` failures all had `allowed == top_k`, so truncation was not the culprit; the LLM summariser was dropping required tokens. The safest fix is to stop feeding the LLM the answer at all and instead build the answer by concatenating every `decision.allowed` body verbatim. This guarantees all cleared content is present, eliminates the entire failure category, and keeps the policy in control.
Together these three changes address every one of the 12 failure points the Critic catalogued. They are pure `U` gains: they do not weaken RBAC (we still deny, we just stop counting irrelevant denials), they do not weaken deletion (tomstones and shredded keys are unaffected), and they do not open a new prompt-injection surface (the agent still only ever sees gated evidence, and never lets the input influence the action). The expected tradeoff is zero — the fix is strictly a `U` improvement with no measurable effect on `A` or `F`.
