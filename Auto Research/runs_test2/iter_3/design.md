## Iteration 3 — Design Document
### Primary target: U (utility_accuracy = 0.333, dominant term, +0.627 contribution)
The previous iteration pinned every U failure to three mechanical bugs, none of which touch the RBAC or forgetting invariants. This iteration fixes all three at their source, keeps the local test suite green (the `answer`/`answer_redacted`/`refuse`/`no_memory` action vocabulary is fixed by `tests/`), and makes **no** change that widens what a requester may read — so A and F are held flat while U is lifted.
### Failure 1 — `answered_but_content_missing` (6 checkpoints): top_k truncation
`retrieve()` stops collecting once `len(decision.allowed) >= 8`. Every responsive row past the cap — including the rows carrying the required tokens ("Friday April 4 at 2:00 PM EEG") — is silently dropped, producing `allowed=8` with empty content. The fix is to delete the `break` and surface **every** matching row. This cannot dilute A: every row that lands in `allowed` has already passed the tombstone → RBAC → relationship/scope gates, so returning more rows returns more *authorized* content, never unauthorized. It cannot raise F: tombstoned rows still go to `denied_tombstone` first and their bodies never enter `allowed`.
### Failure 2 — `evidence_withheld` (4 checkpoints): tombstone short-circuits allowed content
`sanitize_and_decide` returns `no_memory` the instant **any** tombstone is touched, even when `allowed` is non-empty. For `post_delete_recovery` checkpoints this kills surviving content the benchmark expects us to answer from. Fix: reorder the decision branches so a non-empty, denial-free `allowed` set wins over `touched_deleted`. The `answer_redacted` branch — required by `test_partial_authorization_is_redacted` — must be retained for `allowed + touched_unauthorized`, so I do **not** delete it as the previous critique proposed (that would break the local contract).
### Failure 3 — `wrong_action_shape` (2 checkpoints): marginal denied rows force `answer_redacted`
Both cases carry `allowed=8, denied_rbac=1` with a complete answer body. Because the responsiveness filter admits any fallback-path row sharing **one** distinctive term, a single peripheral row lands in `denied_rbac`, flipping the action to `answer_redacted`. The fix is at the retrieval layer, not the agent: for rows found by the plain-scan fallback (which did **not** match all query terms in FTS), require ≥2 shared distinctive terms before treating the row as responsive at all. A row that is not genuinely responsive is neither allowed nor denied — it is simply not part of the query. Rows found via the FTS index already matched **all** query terms, so they keep the ≥1 rule unchanged. This preserves the test contract (`answer_redacted` still fires when `denied_rbac` is genuinely non-empty) while making the two checkpoints emit a clean `answer`.
### Storage constraint
SQL-only is preserved; no new engine, no graph store. The only DDL change is one secondary index on `access_log` to accelerate the Critic’s per-checkpoint evidence census, plus a `SCHEMA_VERSION` bump so a migrated store self-reports its generation.
### Metric accounting
- **U:** +0.63 contribution from the 12 fixed checkpoints → MGS moves from 0.3137 toward the 0.85 target.
- **A:** unchanged. We never add a row to `allowed` that failed a gate; we only (a) return more passing rows and (b) stop *denying* rows that were never responsive. A can only shrink false denials, never introduce a leak.
- **F:** flat to slightly at risk. The narrow case "tombstone + surviving records" now answers with survivors. Tombstoned bodies are still never returned, so direct and implication reconstruction of the deleted fact remain blocked; the `confirm_yes_no` invariant (existence known, content silent) still holds because `retrieve` filters tombstoned rows before `allowed` is populated.
