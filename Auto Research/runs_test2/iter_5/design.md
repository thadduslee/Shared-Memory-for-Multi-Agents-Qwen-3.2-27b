# Iteration 5 Design — Fix U’s two loss mechanisms without opening A/F
## Diagnosis (accepting the census)
Measured MGS 0.3569, target 0.85, and the marginal contributions confirm U is the only term that matters right now: U contributes 0.3569 of the score, A 0.0765, F 0.0549. Both Critique mechanisms are design fixes in code I already own; no infrastructure rebuild is justified. I attack the larger mechanism first (6 checkpoints), then the second (3), and add one **necessary** safety guard the Critique did not spell out so that the first fix does not silently destroy F.
## Why the first fix is not free — and the guard that makes it safe
The Critique tells me to delete the relevance short-circuit so every row that clears tombstone/RBAC/scope reaches `decision.allowed` regardless of token overlap. That is correct for U, but it is unsafe **as stated** because of a row the Critique did not flag: the deletion‑request turn itself.
In `ingest_turn` a delete‑request turn (e.g. `"Actually, delete 555-0142 from the shared assistant memory."`) is inserted as a *regular* record before `_honor_deletion_request` runs. That record is **not** tombstoned (only its earlier targets are). Today it never leaks only because the lexical gate happens to discard it (the distinctive terms of the request body share zero overlap with a query like `"callback number"`). If I simply delete the gate, that request record becomes `allowed` for the patient (and any `self`-granted role), its body re-surfaces `555-0142`, and `test_deleted_content_is_not_retrievable_by_anyone` — the Developer’s own F gate — fails immediately, dropping F.
So the U fix requires a *concurrent* F-protection: a **retire** flag. Delete‑request turns get `retired = 1` at ingest; the retrieval SQL filters `r.retired = 0`, so the blob containing the secret never enters `allowed`, never registers as a denial, and never confirms existence. This is a schema change (one column + one partial index), explicitly emitted below.
The second safety change: the retire flag also removes the other latent U regression inside the current code — the FTS short‑list. Today, when a query matches *any* routine/restricted body in the episode, `retrieve()` limits `rows` to *only* the FTS candidates. A semantically‑required row with zero token overlap (the exact `pre‑op instructions` / `no deodorant on biopsy morning` case) is then never examined at all, so it can never be allowed — the same symptom as the lexical gate, triggered by a different line. The fail‑safe fix is to always run the patient‑scoped, seq‑ordered scan and let the three gates decide; FTS is kept only to populate `from_fts` for the denial‑responsiveness heuristic, exactly as the Critique’s mechanism‑3 wants. No FTS behavior is removed from the write path, so no test that touches indexing changes.
## Mechanism 1 — `MemoryStore.retrieve()` (6 checkpoints, `answered_but_content_missing`)
- Remove the block `if terms and not (terms & _distinctive_terms(plaintext)): continue`.
- Always evaluate every patient‑scoped, non‑retired, `seq <= as_of` row through the gates in order: tombstone → retired/exists → plaintext → RBAC grant → relationship/scope → `allowed`.
- Keep `_is_responsive_for_denial` untouched (`from_fts` still computed) so irrelevant unauthorized rows are *not* elevated into `denied_rbac`/`denied_scope` and do not flip the action to `refuse`/`answer_redacted`. This preserves the anti‑noise property (Critique mechanism 3).
- `allowed` rows are appended with their real `body` regardless of overlap → the concat answer now contains the required fragment.
## Mechanism 2 — `sanitize_and_decide()` + `GateMemAgent.query()` (3 checkpoints, `evidence_withheld`)
Add an explicit, unbreakable invariant at the top of `query()`: if `decision.allowed` is non‑empty, the action **must** be `answer` or `answer_redacted`. Implement both the guard inside `sanitize_and_decide` (a final defensive branch) and a forced overwrite in `query()` that overrides any `no_memory`/`refuse` when `allowed` is truthy, logging `debug.rationale = "forced_overwrite: allowed non-empty"`. This makes the recorded `allowed=1 + action=no_memory` state impossible even if some path outside the visible code produced it.
## Schema change (the only DDL)
`records.retired INTEGER NOT NULL DEFAULT 0`; partial index `idx_records_active_patient(patient_id, seq) WHERE retired = 0` to accelerate the always‑on full scan.
## Cost / benefit to MGS
- U: the dominant term rises by removing two independent recall killers → expected +0.30–0.40.
- A: the wider `allowed` set stays within each requester’s grant (RBAC/scope unchanged), so A risk ≈ +0.01 (irrelevant‑but‑authorized rows now answer; they were authorized anyway).
- F: the retire flag + tombstone‑first ordering + body‑wipe/shred keep deleted and delete‑request text out of the wider `allowed` set → F stays ≈ 0.
- Net: MGS ≈ U·(1−A)·(1−F) moves from 0.357 toward 0.85 with the caveat that the answer concat grows (a small U risk on verbosity, dominated by recall gains).
